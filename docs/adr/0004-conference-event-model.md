# 0004. 大会与小会议分成两层实体

## 状态

已接受

## 背景

Veto 旧模型把 `Conference` 视为一场完整大会，并把内阁、委员会、MPC、学团 IPC 都放在同一个
Conference 内。实际使用中，一场活动通常是“枣庄市第17届模拟联合国大会”这样的大会，下面包含
美国内阁、英国内阁、MPC 等多场小会议。每场小会议有自己的主席、席位、议事状态和局域网服务。

新闻与局势更新需要跨小会议共享：MPC 起草的新闻、学团发布的局势，应被大会内所有代表看到。

## 决策

- 新增 `ConferenceEvent` 作为大会根实体。
- 保留现有 `Conference` 代码名，但领域含义降级为大会下的一场小会议。
- 每场 `Conference` 独立拥有主席、席位、议事状态、指令与局域网生命周期。
- 角色模板属于 `ConferenceEvent`，小会议创建席位时引用并覆盖角色模板权限。
- 新闻与局势更新属于 `ConferenceEvent`，在小会议之间全局共享。
- 第一版仍保留各小会议独立运行在 Chair 本地；未来云端方案再解决跨局域网的大会统筹。

## 后果

现有 Conference 路由、引擎和存储不需要一次性重命名，迁移风险较低。旧数据会被视为未归属大会的
小会议，并可由迁移逻辑补建一个单会议大会。后续云同步以 ConferenceEvent 为聚合边界，小会议
仍保持本地可运行。
