# C端 Sidebar 采用"会议运行时"而非 SaaS 管理后台架构

Veto C端（Electron）的 Sidebar 采用持久化上下文感知导航：无大会时仅显示"首页"，进入大会后展开议程/指令/新闻/局势/军事推演。设置、插件、账户全部移至 TitleBar。明确拒绝 shadcn 风格的 SaaS 后台导航模式（工作台/管理/开发者/系统分组）。

## 考虑过的选项

### A: SaaS 管理后台风格（当前实现）

Sidebar 使用 shadcn Sidebar 组件，分组为"工作台""管理""开发者""系统"。这是当前代码的实现。

**拒绝原因**：Veto C端不是管理工具。用户打开它的目的是加入会议、运行模拟、参与推演，而不是管理数据。分组中的"管理"（组织、模板、数据分析）和 nav-user 中的"Upgrade to Pro / Account / Billing"是 SaaS 后台的思维惯性，与会议运行客户端的定位矛盾。

### B: 进入大会后替换 Sidebar

全局 Sidebar（首页/插件/设置等）→ 进入大会 → 完全替换为会议工具栏。类似 VS Code 的"打开文件夹后侧边栏换成文件浏览器"。

**拒绝原因**：Veto 窗口只有 1200×720，会议工具栏中的 7 个区域已经足够作为独立入口。替换式导航让用户在"全局"和"会议内"两个模式间切换，增加认知负担。而且"我的大会"作为启动器页面，和"议程/指令/新闻"等会议工具之间不需要一道硬边界——用户在大会内也可能想回到大会列表。

### C: 持久化上下文感知 Sidebar（采用）

Sidebar 始终保持 6 项：首页、议程、指令、新闻、局势、军事推演。无大会上下文时，除"首页"外的 5 项隐藏。TitleBar 加上下文指示器显示当前大会名。

**采用原因**：
- 始终可见的布局让新用户一眼看到完整功能范围
- 灰色/隐藏状态传达"需要先打开大会"的引导
- 设置/插件/账户移入 TitleBar，Sidebar 聚焦于会议运行功能
- 与 B端 Web 管理后台形成清晰分工：**B端管理会议，C端运行世界**
